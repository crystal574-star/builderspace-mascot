# 模块接口约定 v0.1

本文件 v0.1 仅约定早期 S3 屏幕/无线快照；第 7 节规定完整版后续接口的设计边界，具体消息需实现前升级版本。尚未由实现验证；不是 echo agent 官方网络协议。总集成人负责维护版本；不得暗中改变字段或状态含义。

## 1. 数据路径与职责

`echo agent → Mac 桥接程序 → 局域网 Wi-Fi → S3 状态管理 → 本地动画 → SPI 屏幕`

- echo 是真实任务状态的来源；桥接程序负责获取、验证和转发，不推测任务完成。
- 固件在本地绘制表情，不传输连续视频或逐帧图片。
- 无任务连接时仍可眨眼；网络和显示任务互不阻塞。
- 预览、演示和真实 echo 模式必须可识别，不能把手动状态作为真实接入证据。

## 2. 状态与表情

| state | 表情方向 |
| --- | --- |
| idle | 平静、眨眼、偶尔移动视线 |
| listening | 专注；仅表示主机状态，不表示设备已启用麦克风 |
| working | 思考 |
| waiting | 注视前方、待确认标志；审批在电脑上完成 |
| done | 开心 |
| failed | 困惑 |
| offline | 困倦、断线标志 |

“开心”等视觉名称留在动画模块，跨模块传递使用上表中的 state。未知 state 按离线/不可用处理，并记录诊断，不显示为任务成功。

## 3. S3 内部调用边界

具体函数签名由总集成人建立公共头文件后冻结，职责如下：

- 屏幕模块：初始化屏幕、更新矩形像素区域、设置亮度；不读取 Wi-Fi 或 echo 状态。
- 动画模块：接收 state 和经过的时间，生成画面；不包含网络请求。
- 状态模块：接收并校验快照、判断过期、选择显示状态；不直接执行任务或批准操作。
- 网络模块：连接网络、取得快照、重连；不直接绘图。
- 板级配置：唯一维护 GPIO、屏幕旋转、颜色顺序、背光方式和屏幕尺寸的地方。

建议固件目录：`firmware/main/{board,display,animation,state,network}/`。先沿用原电脑 ESP-IDF 5.4.1 作为待验证基线，首次实际构建后记录精确依赖；不要将 K151 板级配置直接当通用 S3 开发板配置，必须核对实际板型。

## 4. 第一版无线快照

采用 S3 每秒向电脑桥接程序请求一次快照的简单方案：`GET /v1/device/status`。主机地址在初次配置中提供，第一版无需自动发现或公网服务。设备鉴权凭据通过配置提供，不写入仓库。仅用于受信局域网；此原型不等同于官方加密配对协议。

建议响应：

```json
{
  "version": 1,
  "mode": "demo",
  "session": "bridge-start-unique-id",
  "seq": 1,
  "state": "working",
  "source_connected": true,
  "working": 1,
  "waiting": 0
}
```

- `mode` 只能为 `demo` 或 `echo`。预览页面和设备通过小标记显示模式，面部仍为主要内容。
- `session` 在桥接程序重启时更换。新会话只在重新建立并验证连接后接受，清空旧序号和旧结果。
- `seq` 在每次发布的心跳快照中严格递增，旧序号不覆盖新状态，也不刷新有效快照超时。
- `state` 采用第 2 节枚举；计数必须为非负整数；首版不传对话内容或任务标题。
- `source_connected=false` 时设备显示 offline。桥接程序仍能响应 HTTP，并不表示真实 echo 仍在线。
- 设备连续 5 秒没有新的有效快照进入 offline；网络恢复后重新同步，不重放旧动作。
- echo 源的有效性按原设备协议判断：未握手或有效状态超过 75 秒未更新，桥接程序发布 offline。桥接程序自身心跳不得伪造 echo 源心跳。
- 连接恢复后，任务状态由最新快照决定，不由设备推测。

这些超时是两个不同层次：5 秒判断 S3 到桥接程序的链路；75 秒判断桥接程序到 echo 的上游状态。

## 5. 演示控制与真实接入

电脑提供本地演示控制页，可选择七种状态和调整演示计数。演示控制仅在 demo 模式生效，不发送任何真实审批或任务命令。

真实模式优先验证既有模拟器的 PTY / `ECHO_DEVICE_PORT` 接入路径，读取原始设备协议 status，再映射到本快照。原来的状态页只监听 `127.0.0.1`，不能原样当作 S3 可访问的局域网接口。

此路线尚未通过真实 App 验证。桥接负责人需要用已安装 echo agent 验证握手及状态，不可把 probe 测试主机当作真实 echo。原生 Wi-Fi 协议仍是参考仓库中的草案，不将其当作现成 API。

## 6. 硬件接口

候选屏幕信号：VCC、GND、DIN/MOSI、CLK、CS、DC、RST、BL。供电与背光接法依实际模块电路确认；S3 信号采用 3.3V 逻辑。

硬件负责人取得实物信息后交付唯一的 GPIO 表；软件和外壳共同引用该表。外壳以屏幕完整 PCB、连接器和线缆空间为边界，不能只按显示区域开模。

## 7. 完整版模块契约：分阶段冻结

以下是职责边界与必须交接的字段清单，不是可直接调用的已实现 API。每个阶段开始前由 T0 与对应模块负责人补齐精确类型、示例、错误与版本兼容方式。

| 接口 | 生产方 → 消费方 | 至少包含 | 冻结阶段 |
| --- | --- | --- | --- |
| 视觉参数包 | T1/T13 → T4 | 布局尺寸、眼睛嘴巴参数、主题、过渡时间、资源版本/来源 | P1 |
| 触摸事件 | T9 → T10 | 部位、按下/释放、事件序号、本地单调时间；去抖与冷却语义 | P2 |
| 行为请求 | T10 → T4/音频/动作 | 行为名、来源、优先级、有效期、取消标识 | P2，后续版本扩展 |
| 状态快照 | T6 → T5/T10 | 第 4 节快照、上下游有效性 | P3 |
| 使用模式 | T14 → 主机与设备 | desk/event、切换会话、允许功能；切换成功确认 | P3–P5 |
| 语音会话 | T11 主机 ↔ 设备 | 会话 ID、格式/采样率、开始/音频/结束、取消、限长、错误 | P4 |
| 活动内容包 | T12 → T11/T14 | 内容版本、语言、介绍/FAQ、审核人与日期、资源引用、二维码目标 | P5 |
| 硬件装配包 | T2/T7/T15 → 所有固件/操作者 | 主控版本、GPIO、供电、尺寸、连接器、BOM、装配/恢复图 | 每次换硬件 |

### 行为、状态和模式不要混为一谈

- v0.1 的 `mode=demo/echo` 表示数据来源；完整版的 `desk/event` 表示使用场景，是另一个维度。不能把 event 直接写进原 mode 字段。
- 连接状态、任务状态、角色情绪分别保存。掉线时可以用角标提示，仍回应本地触摸；具体组合规则在 P2/P3 与总集成人冻结。
- 真实任务状态是主机事实，触摸开心是短时角色反应；短时反应结束后回到最新有效状态，不修改真实任务结果。
- 模式切换结束旧对话/播放与待执行互动，取消关联会话；活动模式不显示旧个人任务，重连不恢复被取消的操作。
- `waiting` 仅提示电脑待确认；任何摸头、拍打、活动访客互动都不触发个人任务审批。

### 语音和内容

先使用半双工；录音入口明确且有视觉指示；播放与录音可取消，缓冲有界。格式、包大小、鉴权和传输另行评审，不能把现有只读快照 HTTP 接口当成已支持语音上下行。

离线语音资源由 T12/T11 提供并核验容量；录音、识别文字、对话内容不默认持久化。活动内容只能来自审核的内容包或被允许的社团资料，未知问题返回简短说明。个人凭据与工具权限留在主机。

### 并行修改归属

T5 维护 network 与连接/快照校验，T10 维护新增 behavior 目录及行为仲裁，T4 维护动画。T0 维护共享类型和入口。T11 新建 audio，T9 新建 input，T14 管理模式/配置；不得各自复制出第二套互相矛盾的状态定义。
