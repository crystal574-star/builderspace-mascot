## 真实 echo 实验：P0，先验证现有协议

前置：macOS、已安装 echo agent、Python 3.10+、上游 echo-agent 参考源码；不要让 probe 和真实 App 同时打开一个模拟端口。

1. 在上游参考源码目录启动无麦克风模拟器：

```sh
python3 device/sim/sim.py --link /tmp/builderspace-echo-probe --ui-port 0 --mic none --name BuilderSpace-Probe
```

2. 协调空闲时机并正常退出 echo App。以下命令必须启动一个新的 App 进程；对已运行的 App 执行 open 不会让它重新读取环境变量。使用本次临时环境，不写入全局 launchctl 配置：

```sh
env ECHO_DEVICE_PORT=/tmp/builderspace-echo-probe open -a 'echo agent'
```

macOS/应用启动方式可能不传递所需环境；若未收到握手，核对具体版本的启动方式，再在已退出 App 后从终端用同样环境启动其实际可执行文件。不要重复启动多个 App 实例或打断正在工作的任务。

3. 模拟器输入 `wait connected 30`，确认连接日志的主机是 echo 而不是 probe。输入 `status` 记录有效 seq、状态和 App 版本；先不要使用 tap 或 hold，避免真实审批/语音派活。
4. 握手通过后，用用户选择的无副作用小任务验证状态变化；需要 waiting/failed 的完整验收可安排后续，不为了制造失败或审批执行危险操作。
5. 保存经脱敏的结果摘要到 STATUS；原始日志仅放忽略目录 `local/`。退出模拟器，正常重开 App 恢复普通启动方式。

成功条件分开记录：A 真实握手；B 收到新状态；C 真实任务造成状态变化。只能满足其中一项就只标那一项。失败路线见 REVIEW，不把 demo 改名为 echo。
