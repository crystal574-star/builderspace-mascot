# 完整版可分发任务书

所有执行者先读根目录 README、INTERFACES 和 STATUS。以下是建议分工，不表示已派发任务或已有人认领。

先读 MASTER_PLAN 确认完整版愿景，再读 PHASES 中自己参与的阶段。原 T0–T8 编号保留；新增 T9–T15 覆盖完整版。每个任务只有一名交付负责人，可拆执行子任务但必须有人整合。先交付 P1，其他工作按依赖并行。

## 四个交付负责人，模块编号仅作索引

A 总集成与固件/硬件：T0/T2/T3/T4/T5/T8/T9/T10/T11B/T15；B 表情预览：T1 并协作 T13；C 电脑桥接：T6/T11A/T14；D 内容与角色：T12/T13/T7。只有四个工作包，不要求十六个人。所有人选待认领，可由同一人兼任。下面保留模块任务边界供未来拆分。

## 可直接发给每个执行者的任务

### T0 总集成

你负责 BuilderSpace 完整吉祥物总集成。第一阶段建立可构建的 S3 表情工程、共享状态类型和模拟输入接口；按 MASTER_PLAN/PHASES 推进触摸、无线、语音和活动样机，不能把 P1 当作完整范围。确认各任务负责人、目录边界和接口版本。分阶段合并，记录构建环境和版本；P4 音频 GPIO 和资源统一评审。不要替执行者宣称未做的实测；每次集成附运行说明和验证证据。接口变更集中更新 INTERFACES，并通知依赖方。

### T1 表情设计与预览

你负责屏幕上的脸。目标为横向 320×240 布局，黑底、眼睛为主、嘴巴为辅。输出 idle/listening/working/waiting/done/failed/offline 七态，以及眨眼、视线移动和过渡参数。提供可本地运行的预览、参数表和预览截图；在实际约 40.8×30.6mm 可视区域大小下检查辨识度。使用简单几何形状表达，便于 S3 移植；前端效果不代表固件已实现。不接 echo、不改驱动。

### T2 硬件与采购

你负责核对拟购带 PSRAM 的 ESP32-S3 板型、排针、USB 和屏幕组合，C3 保留为已有库存。核验候选屏幕的驱动、供电、配套连接线与机械尺寸，交付带实物照片依据的接线表和一台样机 BOM，分别标明已有、必买、可选、后续。先验证一块屏幕；未经实物核对不冻结 GPIO。不采购音频、舵机或电池模块。

### T3 屏幕驱动

你负责在核对后的 S3 和屏幕上实现初始化、方向/色序、矩形刷新和亮度控制。驱动不得包含网络或表情业务。交付源码、可重复构建与刷写步骤、GPIO 配置、红绿蓝与方向测试照片。目标至少稳定运行 30 分钟，记录实际结果。没有真机时交付编译结果和待测清单，不宣称已点亮。

### T4 表情固件

你负责把 T1 的视觉参数实现为 S3 本地动画。采用局部刷新或小缓冲，避免依赖大尺寸连续帧素材；离线仍可眨眼。支持七态切换，动画不阻塞网络。交付源码、演示模式、参数说明、内存和实测帧率记录；15–25fps 是待验证目标。无网络时也要能演示完整表情。

### T5 无线固件

你负责 S3 连接 Wi-Fi、读取 v0.1 快照、状态校验、超时、重连和配置保存。先用 T6 的 demo 服务开发，不等待真实 echo。交付配置说明、故障诊断和断网/桥接程序停止/上游离线/重启/旧序号验证结果。保持显示任务运行；不实现审批、语音、蓝牙或官方尚未发布的无线协议。

### T6 电脑桥接与控制页

你负责本地演示控制页、v0.1 快照服务及真实 echo 数据接入。第一项工作是验证现有 PTY / ECHO_DEVICE_PORT 路线在已安装 echo App 上是否可用，记录 App 版本、握手和状态证据。demo 模式与 echo 模式清楚区分。只转发状态与计数，不转发对话、凭据或执行审批。原服务绑定 localhost 的限制须正确处理。真实源不可用时交付 demo 和明确阻塞证据，不把它标记为真实接入完成。重启正在处理工作的 App 前先协调用户操作时机。

### T7 外壳结构

你负责形成社团玩偶的简单可维修外壳。先交付草图与尺寸假设；取得实物尺寸后，预留完整屏幕 PCB、S3、连接器、线材弯折、固定点和电源接口空间。保证屏幕不受挤压、USB 可访问、天线区域无遮挡设计依据，并提供装配说明。第一版固定机身，不含运动机构。交付可编辑模型和打印文件、尺寸表及装配照片；尚未实物装配必须注明。

### T8 整机验收

你负责按 PHASES 的 P1–P6 分阶段验收，可选 P7 另立清单。分别记录模拟器、编译、真实屏幕、触摸、无线演示、真实 echo、语音、活动模式、断网和装壳测试，不能混用证据。记录代码版本、设备/屏幕型号、供电、步骤、预期与实际。P3 必须有真实任务证据，P5 验证活动/个人边界，P6 包含两小时运行与未参与成员操作测试。旧 M 编号只作为历史技术检查点。

### T9 摸头传感与输入

你负责优先用 S3 原生触摸与电极实现一个摸头区域的触摸传感、电极、去抖、释放和冷却。先测试临时壳体材质，再交付硬件位置与事件接口。按 PHASES 的 P2 验证触发率和误触。仅发触摸事件，不直接切网络状态或批准操作。交付源码、接线、电极/材质照片、阈值与真机记录。

### T10 角色行为协调

你负责把空闲、触摸、任务、说话与活动脚本协调成一个角色。输出优先级、有效期、取消和回归规则；维护 behavior 目录，不复制 T5 的网络状态机或 T4 的绘图代码。P2 先完成摸头开心后回待机；P3 保留最新真实任务；P4 协调录音/说话；P5 防止桌面任务打断活动介绍。交付状态/事件表、可模拟的演示和冲突测试。

### T11 语音与对话链路

你负责 P4 的主机和设备声音闭环。可分 T11A 主机适配与 T11B 音频固件，但共同冻结一份接口，由一人整合。先验证电脑侧和 echo 已有入口/结果，再与 T2 冻结 S3/集成音频方案、引脚和供电；使用 P1 已选 S3，先核对资源再买音频配件。先固定音频播放，再按住录音，再识别/回答，再 echo 派任务。采用半双工、会话 ID、限长和取消。交付硬件评审、代码、接口、语音用例、错误分类和实测；缺少主机音频下行时明确记录适配缺口。普通自由聊天成功不等于 echo 派任务已完成。

### T12 社团内容与知识包

你负责吉祥物自我介绍、30/90秒社团介绍、至少10条 FAQ、项目讲解、加入/联系指引和已审核链接。可在 P1 开始准备。社团成员确认事实、语气、语言、授权素材与更新时间；agent 可整理草稿但不替社团批准内容。交付可编辑文本和机器可读内容包、版本/审核记录，配合 T11 生成并检查离线播报。缺少的信息标为待确认，不编造。

### T13 角色与完整外观

你负责有辨识度的 BuilderSpace 角色：名字候选、性格、正侧背概念、脸与身体比例、触摸位置、色彩和素材来源。先出概念，不抢先固定软硬材质或舵机。用户/社团确认后交给 T7 建模；T1 的表情需与角色统一。交付可编辑源文件、尺寸假设、社团确认记录和复用规范。P1 预览可先用临时脸，外观决策不得阻塞点屏。

### T14 模式与维护入口

你负责管理员明确切换 desk/event，以及保留 demo/真实数据来源标记。管理亮度、音量、静音、网络诊断、内容版本和恢复入口。活动模式仅使用社团内容与允许功能，不能调用个人工具；切换时取消旧对话与播放并清除个人结果展示。交付配置/模式接口、控制页面、操作卡和隔离测试；不要把当前快照接口擅自扩成语音 API。

### T15 供电、携带与现场部署

你负责桌面供电、移动电源适配、线材固定、运输和活动网络/主机清单。先测最终硬件功耗和移动电源自动关断，再报告实际运行时间。默认优先成品 USB 电源，不先拼裸电池。活动预演明确谁带主机、谁带热点、无网可用什么；制作开机/关机/故障/收纳清单。交付测量记录、现场依赖、照片和备件清单。

## 第一批可分发组合

- 表情组：T1；后续接 T4，与固件成员协作。
- 硬件组：T2；有实物者协作 T3/T9，后续 T15。
- 接入组：T6 先调查真实 echo；P3 接 T5/T14。
- 社团设计与内容组：T12/T13，可立即准备素材与草稿，等待社团确认。
- 总集成：T0 贯穿所有阶段，T8 各阶段验证。

每个接手者收到整个文档目录和对应源码，而不是只有一段聊天或本任务标题；使用 STATUS 的模板提交交接。

## 统一交付要求

每项交付包含：文件/提交位置、启动或构建命令、接口版本、证据、限制、下一接手者需要做的第一步。软件 agent 负责源码与可复现步骤；实物操作者负责插接、拍照、测量和真机验证。仅完成代码编写不能代替硬件验收。
